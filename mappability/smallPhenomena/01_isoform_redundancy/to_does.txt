────────────────────────────────────────────────────────────────────────────────

Q: How much signal can be gained from shared protein domains
   (MANE + hmmscan + MAFFT + mappability)?
   Abbrev   : hmmscan = HMMER tool for searching a protein sequence against a
              profile HMM database (e.g. Pfam); identifies conserved domain regions
              Pfam = database of protein family profile HMMs
              profile HMM = probabilistic model of a multiple sequence alignment
              domain = contiguous protein region matching a Pfam profile HMM above
              the inclusion threshold (E-value < 0.01 by default)
              domain coordinates (aa) → transcript coordinates (nt): multiply aa
              position by 3, add CDS start offset from transcript start
              shared domain = Pfam domain present in ≥ 2 members of a paralog family
   Analysis : new analysis (not yet in analyze.py)
              step 1: run hmmscan (Pfam database) on MANE Select protein sequences
                      input:  MANE.GRCh38.v1.5.ensembl_rna.fna → translate CDS
                      output: per-gene domain table (Pfam accession, aa start/end,
                              E-value, score)
              step 2: map domain aa coordinates to transcript nt positions
                      using CDS position within MANE transcript
              step 3: extract domain-region sequences and inter-domain sequences
                      from MANE RNA FASTA
              step 4: compute frac_unique (31-mer) separately for
                      (a) domain regions only
                      (b) inter-domain / terminal regions only
              step 5: run MAFFT pairwise alignment within each shared domain
                      across paralog family members (as in Section G Option A)
              step 6: compare pct_identity within domain vs outside domain
              output files (proposed):
                      domain_annotations.tsv    — gene × domain table
                      domain_kmer_uniqueness.tsv — frac_unique inside vs outside domains
                      domain_homology.tsv        — MAFFT pct_identity within shared domains
   Result   : pending

SIGNATURE SEQUENCES
────────────────────────────────────────────────────────────────────────────────

Q: Can we define a signature sequence for each MANE gene to simplify k-mer-driven mapping?
   Abbrev   : unique stretch = the longest contiguous run of transcript positions i
              where seq[i:i+31] is a unique 31-mer (not present in any other MANE
              transcript); each step in the run adds 1 bp
              stretch span (bp) = N_positions + 30  (N positions of 31-mers, each
              overlapping the previous by 30 bp)
              minimum reportable: 1 unique 31-mer → 31 bp span
              target: ≥ 20 consecutive positions → ≥ 50 bp span; a 50 bp unique
              region can tolerate short indels or mismatches that shift k-mer
              positions by a few bp while still landing on ≥ 1 unique 31-mer
              optimal: the longest such stretch, regardless of target threshold
              max_unique_stretch_bp = span of the longest unique run per transcript
              stretch_reaches_50bp  = 1 if max_unique_stretch_bp ≥ 50, else 0
   Analysis : Section C → isoform_kmers_mane.tsv
              columns: max_unique_stretch_bp, max_stretch_positions,
              stretch_start_nt, stretch_reaches_50bp
              (computed in max_unique_stretch() in analyze.py, runs as part of
              the existing k-mer pass — no additional analysis step needed)
              step 2 (proposed, not yet implemented): record stretch position
              relative to transcript structure: 5'UTR / CDS / 3'UTR using
              MANE transcript CDS coordinates from MANE summary table
              output (proposed):
              signature_sequences.tsv — gene_name, enst_id, stretch_start_nt,
              stretch_end_nt, max_unique_stretch_bp, stretch_region
              (5UTR / CDS_start / CDS_internal / CDS_end / 3UTR),
              stretch_reaches_50bp
              for UTR-fail genes: record max_unique_stretch_bp achieved;
              genes with max_unique_stretch_bp = 0 have no unique 31-mer anywhere
   Result   : pending
